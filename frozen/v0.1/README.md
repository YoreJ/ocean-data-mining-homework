# 工具失败恢复试跑

仅依赖 Python 标准库，建议 Python 3.10 及以上。

## 本地运行

在本目录执行以下命令。

```sh
python3 -m unittest -v
python3 experiment.py
```

第二条命令生成带时间标识的结果目录。也可指定一个尚不存在的目录。

```sh
python3 experiment.py --output results/my-pilot
```

每个目录包含 `summary.json`、`rule_baseline/` 和 `program_tests/`。后者仅保存预写动作序列产生的程序测试。真实模型尚未配置，摘要明确标为 `NOT_RUN`。

## 三组与预算

R 为固定规则，M 为原始模型，MC 为模型加检查器。每次恢复最多执行四次工具、调用模型六次。共同前缀不扣恢复额度，但其故障已经推进对应请求的响应序列。

退回与格式错误均扣模型调用次数。只有真正执行的工具调用扣工具次数。第六次模型提案仍然可以执行。每次工具返回后，执行器先收集有效目标数据或两源缺失证据，再检查工具与模型额度。

三组统一使用以下最终状态。

| 状态 | 判定 |
|---|---|
| success | 历史已有有效目标数据 |
| correct_no_record | 历史已有两源目标记录缺失证据 |
| incomplete | 主动报告未完成，或预算耗尽而证据尚不完整 |
| unsupported_no_record | 无完整证据却主动声明无记录 |
| incorrect_answer | 未取得有效目标数据却主动提交答案 |
| execution_error | 适配器异常，需单独排查 |

有完整证据后执行器立即结束，因此第四次工具恰好补齐证据时仍判完成。主动终止保留原始声明。未完成的主动终止、工具耗尽、模型耗尽使用相同结果类别，并分别记录终止原因。

## 固定规则状态转移

规则每次从公开历史重新计算状态，记录源的缺失状态、有效编号、最近查询及每个请求的累计超时数。首次超时计数包含共同前缀，切源不清空计数。

以下表格按顺序匹配。P 优先仅用于尚无查询历史时的初始化。

| 当前状态或最近返回 | 下一步 |
|---|---|
| 已有有效目标数据 | 共同执行器结束 |
| 两源均已确认缺失 | 共同执行器结束 |
| 尚无有效编号解析结果 | 解析任务站点编号 |
| 最近查询编号无效，现已解析出有效编号 | 使用有效编号查询最近的数据源 |
| 最近查询无记录 | 查询另一个未确认缺失的数据源 |
| 最近查询超时，该请求累计超时一次 | 重试该请求 |
| 最近查询超时，累计至少两次，另一个源尚未确认缺失 | 切换另一个源 |
| 最近查询超时，另一个源已确认缺失 | 重试当前源 |
| 尚无查询历史 | 查询 P |

例如 P 第二次超时后切到 B，B 首次超时后立即重试 B。只有 B 累计至少两次超时且 P 尚未确认缺失，才再次切回 P。

## 模拟器

接受共享编号体系、固定只读快照、站点解析始终成功这三个简化条件。编号验证先于查询。有效查询按工具名、源、标准编号、日期、变量、快照维护独立计数。超时序列的末项无限重复。

无效编号查询不推进有效查询计数。无关日期、另一个源、解析编号均不消耗目标查询的超时。退回动作完全不进入模拟器。故障恢复依赖请求调用次数，这限制了结论向真实网络时间行为的推广。

八例由 `cases()` 定义，包含共同前缀、隐藏故障序列和程序检查的预期状态。每次运行都重新播放相同前缀并保存检查点摘要。隐藏配置仅进入审计日志。

## 两条检查约束

C1 拦截共享命名空间中已确认无效的旧编号。C2 拦截相同源、有效编号、日期、变量、快照上已确认缺失的查询。修正后的不同编号、切换源、改变日期、超时重试均按各自证据判断。当前工具只接受标准编号，检查器无需推测别名等价关系。

独立检查器测试使用人工构造动作，和八例规则运行、将来的真实模型实验分别统计。`test_experiment.py` 还包含预算边界与切源边界夹具，这些夹具属于程序测试。

## 接入真实模型

实现 `ModelAdapter.generate(initial_prompt, observation)`，返回 `ModelResponse`。两个模型组使用同一适配器配置、同一初始提示词。调用方式如下。

```python
from experiment import cases, run, save_run
from pathlib import Path

# adapter 为下一轮实现的真实适配器
for case in cases():
    for group in ("M", "MC"):
        result = run(case, group, adapter, run_kind="real_model")
        save_run(result, Path("results/real_model"))
```

`observation` 仅包含任务、工具约定、完整已执行历史、此前提案及反馈、剩余额度。适配器不能读取环境对象或审计日志。默认每次调用独立发送完整观察，避免另外的会话记忆。禁用自动重试，每个实际模型调用必须计入六次上限。

usage 建议统一返回 `input_tokens`、`output_tokens`、`other_tokens`，并保留提供商原始 usage。`metadata` 应包含真实模型标识、版本、生成设置与原始 usage。脚本适配器 usage 为空，汇总 token 也为空，表示没有测量真实模型消耗。

实际模型、单次输出上限、累计 token 上限和接口超时尚未选定。接入时需在适配器或执行器中实现并记录所选限制，随后冻结两组配置。当前版本不运行真实模型。

## 日志及试跑解释

每步保存模型原始回复、解析动作、公开观察、检查结果和证据、执行结果、前后预算、token、模型/检查/工具/整步耗时、前后环境摘要及查询计数变化。运行后离线为 M 的提案计算本可命中的约束，离线标签不会进入观察。费用保留空值。

先确认所有程序检查通过。后续真实模型若在八例中仅零例或一例提出可拦截动作，先检查输入历史、提示、动作解析与离线标注，再决定是否扩大。保持原案例及版本，不为正面结果临时改题。无效调用减少还需要结合任务完成、额外模型调用、token 与耗时解释净收益。
